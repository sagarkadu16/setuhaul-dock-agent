SetuHaul Cognito Auth Flow

Drivers log in with a code emailed by Amazon Cognito. Cognito proves who the person is (their sub). Our database decides which driver that is, and checks it again on every request. AUTH_MODE=local keeps the Level 1 email login for tests and offline demos.

1 · Logging in with an email code

Streamlit talks to Cognito directly with unsigned calls, so the UI server holds no AWS credentials. Our API joins at the end, when the new access token is used to open a chat thread.

2 · What every API request goes through

Identity enters in one place, current_driver_id(). Each stage can stop the request with its own status code, so the UI knows whether to refresh, show "contact ops", or wait and retry.

3 · Staying logged in, and logging out

Access tokens last 15 minutes. The UI refreshes once when the API says 401, then retries. Retrying /chat is safe because each message carries the same client_msg_id.

4 · The user pool as code

The hand-made console pool runs the app today. Step 13 replaces it with pools defined in infra/auth_stack.py, one per environment, whose outputs fill the three COGNITO_* settings.
